# 智汇就业前端页面设计方案（TDesign 风格）

## 1. 目标与范围

本方案用于统一 Web 管理端与小程序业务页的视觉与交互，解决当前页面「信息密度不足、空白过大、模块不统一」的问题。  
优先覆盖 4 个核心模块：

1. 基地管理
2. 招聘管理
3. 考勤管理
4. 薪资结算

设计目标：

1. 一眼可读：首屏有关键数据、有下一步动作。
2. 一致可用：页面结构统一，用户切换模块无需重新学习。
3. 易于落地：全部采用 TDesign 现成组件组合，减少自定义成本。

---

## 2. 全局设计原则

1. 结构统一：每个业务页采用「页头 + 指标区 + 筛选区 + 主内容区 + 详情侧栏/弹层」。
2. 信息前置：把 KPI、异常提醒、待处理任务放在首屏上半区。
3. 动作就近：操作按钮放在数据附近，不让用户频繁上下滚动。
4. 空态不空白：空数据状态必须包含说明、下一步建议、快捷入口。
5. 状态完整：每个区块必须定义加载态、空态、错误态、权限态。

---

## 3. TDesign 视觉基线

## 3.1 色彩与语义

本项目固定基础色调为：**浅绿色 + 浅蓝色 + 白色**，并按 TDesign 语义色映射使用。

推荐 Token（与当前代码保持一致）：

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| `brand` | `#58C2A6` | 主按钮、主要操作 |
| `brand-hover` | `#2F8F78` | 按钮悬停/激活 |
| `info` | `#4F98D8` | 次级强调、筛选态、链接 |
| `bg-page` | `#F2FBF8` | 页面大背景 |
| `bg-surface` | `#FFFFFF` | 卡片/表格底 |
| `text-primary` | `#143247` | 主文案 |
| `text-secondary` | `#5F7F93` | 次文案 |
| `border` | `rgba(79,151,180,0.18)` | 分割线/边框 |

建议策略：

1. 页面主色以 `brand` 为主，`info` 仅用于辅助强调。
2. 卡片与表格背景优先使用白色，避免大面积纯色块。
3. 阴影使用蓝绿冷色半透明阴影，减少“厚重感”。
4. 危险态与警告态仅用于状态提示，不参与大面积铺色。

## 3.2 字体与排版

1. 页面标题：20-24px，600-700。
2. 卡片标题：16-18px，600。
3. 正文：14px，400-500。
4. 说明文字：12-13px，400。
5. 栅格与间距：8px 基准，区块常用 16/24/32。

## 3.3 组件风格约束

1. 统一圆角：卡片 12，输入与按钮 8。
2. 统一控件高度：表单控件优先 32/36/40 三档。
3. 统一图标风格：线性图标，不混用多套风格。

---

## 4. 页面骨架模板（所有模块通用）

推荐模板：

1. 页头区：标题、面包屑、主操作按钮。
2. 指标区：3-6 个 `Card + Statistic`，展示今日核心状态。
3. 筛选区：`Form + Select + DatePicker + Input + Button`。
4. 主内容区：`Table` 或 `Tabs + Table`，支持批量操作。
5. 辅助区：`Drawer` 展示详情，`Dialog` 做二次确认。

建议布局：

```text
┌ 页面标题 + 主按钮 ───────────────────────────┐
├ KPI 卡片行（4张） ───────────────────────────┤
├ 筛选栏（查询条件 + 重置 + 查询）───────────────┤
├ 数据区（表格/时间轴/看板）────────────────────┤
└ 侧栏抽屉（详情/编辑）─────────────────────────┘
```

## 5. 模块级页面设计

## 5.1 基地管理（BaseManagement）

页面目标：快速查看基地健康度，处理基地资料与状态。

首屏建议：

1. KPI：基地总数、在营基地、待审核、异常基地。
2. 风险提示条：证照到期、招聘停滞、考勤异常。
3. 基地列表：按状态分段或带状态筛选。

组件组合：

| 区域 | TDesign 组件 | 设计要点 |
| --- | --- | --- |
| 页头 | `PageHeader` `Button` | 主按钮使用「新增基地」 |
| KPI | `Row` `Col` `Card` `Statistic` | 每张卡有趋势或同比 |
| 筛选 | `Form` `Select` `DateRangePicker` | 保留「重置/查询」双按钮 |
| 列表 | `Table` `Tag` `Badge` | 状态用语义色，操作列固定右侧 |
| 详情 | `Drawer` `Descriptions` `Tabs` | 基础信息/招聘/考勤三页签 |

关键交互：

1. 行点击打开详情抽屉，不跳全页。
2. 状态变更使用 `Popconfirm`，避免误操作。
3. 批量操作完成后，顶部显示 `Message.success`。

## 5.2 招聘管理（JobManagement）

页面目标：围绕岗位生命周期组织信息，减少「找不到待办」。

首屏建议：

1. KPI：在招岗位、今日新增报名、待处理申请、即将截止岗位。
2. 工作台卡片：今日待处理事项清单。
3. 岗位列表按状态切换：在招/已满/已下线。

组件组合：

| 区域 | TDesign 组件 | 设计要点 |
| --- | --- | --- |
| 状态切换 | `Tabs` | 按岗位状态分组 |
| 列表 | `Table` `Avatar` `Tooltip` | 岗位名可悬浮展示完整描述 |
| 审核流 | `Timeline` `Steps` | 展示报名处理进度 |
| 快速处理 | `Drawer` `Form` | 审核、通知、备注在同一抽屉完成 |

关键交互：

1. 列表支持「批量通知」「批量通过」。
2. 报名详情支持「上一步/下一步」快速切换记录。
3. 空态提供「去发布岗位」「导入岗位模板」两个动作。

## 5.3 考勤管理（AttendanceManagement）

页面目标：快速识别异常考勤并闭环处理。

首屏建议：

1. KPI：今日出勤率、迟到人数、漏签人数、待复核记录。
2. 异常列表前置：优先显示迟到/漏签/定位异常。
3. 时间维度切换：日/周/月。

组件组合：

| 区域 | TDesign 组件 | 设计要点 |
| --- | --- | --- |
| 时间切换 | `RadioGroup` `DatePicker` | 支持快捷日期 |
| 趋势图 | `Card`（嵌图表） | 展示出勤率趋势 |
| 异常清单 | `Table` `Tag` | 异常类型强语义色 |
| 复核处理 | `Dialog` `Textarea` | 必填处理意见 |

关键交互：

1. 点击异常行直接弹出复核弹窗。
2. 处理完成后该行变为「已处理」并弱化显示。
3. 支持导出当前筛选条件下的数据。

## 5.4 薪资结算（PayrollView）

页面目标：让结算进度透明、可追踪、可回溯。

首屏建议：

1. KPI：待结算人数、待发金额、已发金额、异常单数。
2. 结算周期卡片：当前周期起止时间 + 进度条。
3. 异常账单清单：金额冲突、工时缺失、银行卡异常。

组件组合：

| 区域 | TDesign 组件 | 设计要点 |
| --- | --- | --- |
| 周期控制 | `DateRangePicker` `Select` | 支持历史周期回看 |
| 进度展示 | `Steps` `Progress` | 对齐结算流程节点 |
| 账单表格 | `Table` `InputNumber` | 支持行内校正 |
| 发放确认 | `Dialog` `Result` | 二次确认并展示结果 |

关键交互：

1. 批量结算前展示汇总确认弹窗。
2. 结算后提供「下载对账单」入口。
3. 异常账单支持一键跳转到员工详情。

## 6. 小程序页面防空旷策略（你当前问题的直接解法）

首页和业务页必须满足以下规则：

1. 首屏至少包含「身份卡 + 快捷操作 + 动态内容块」三块。
2. 无数据时显示空态卡片，不允许纯文字单行提示。
3. 每个空态提供 1 个主动作和 1 个次动作。
4. 内容区至少有「推荐」「待办」「最近记录」中的两块。
5. 底部 Tab 上方预留 16-24px 安全区，避免视觉断层。

推荐首页结构：

1. 用户卡片：头像、编号、关键指标。
2. 快捷宫格：岗位广场、工作历程、薪资结算、个人中心。
3. 推荐基地区：有数据显示列表，无数据显示引导卡。
4. 今日建议区：3 条下一步行动建议。

---

## 7. 状态与反馈规范

统一状态组件：

1. 加载态：`Skeleton` 或 `Loading`，禁止长时间白屏。
2. 空态：`Empty` + 操作按钮。
3. 错误态：`Result` + 重试按钮 + 错误原因。
4. 成功反馈：`Message`，持续 1.5-2 秒。
5. 高风险操作：`Popconfirm/Dialog` 二次确认。

反馈文案要求：

1. 说明发生了什么。
2. 说明用户接下来可以做什么。
3. 避免只写「失败」这类无信息文案。

---

## 8. 落地节奏（建议）

第 1 阶段（2-3 天）：

1. 确定全局 Token、颜色（浅绿/浅蓝/白）、圆角、字体、间距。
2. 改造 Layout（页头、筛选栏、内容容器）。
3. 输出 1 个标准列表页模板。

第 2 阶段（3-5 天）：

1. 按模板改造基地管理与招聘管理。
2. 补齐空态、错误态、加载态。
3. 统一按钮文案与状态色。

第 3 阶段（3-5 天）：

1. 改造考勤管理与薪资结算。
2. 增加流程组件（Steps/Progress/Result）。
3. 完成响应式与低分辨率适配。

第 4 阶段（1-2 天）：

1. 走一轮可用性检查与视觉对齐。
2. 修复交互细节（间距、层级、反馈时机）。
3. 形成最终 UI 规范快照。

---

## 9. 验收清单

每个页面上线前必须满足：

1. 首屏无大面积无意义留白。
2. 页面结构符合统一骨架。
3. 关键操作可在 2 次点击内触达。
4. 加载/空/错/成功四类状态齐全。
5. 表格与筛选栏在 1366 宽度下不拥挤。
6. 小程序页面在 iPhone 12/13 尺寸下无遮挡。

---

## 10. 你可以直接执行的下一步

1. 先选一个模块作为模板页（建议 `BaseManagement`）。
2. 先做骨架统一，再填业务内容，不要反过来。
3. 每改完一个模块，按第 9 节做一次验收。
4. 模板稳定后复制到其余 3 个模块，减少返工。
