## Project Overview

**采摘通 Picking Pass** — agricultural workforce full-lifecycle management platform. Covers base onboarding, job posting, worker signup, on-site QR check-in, attendance stats, salary confirmation, payroll, and report export.

### Business Roles

- **worker** — browse bases/jobs, sign up, show check-in QR code, view attendance & salary, confirm wages
- **boss** — submit enterprise/base registration materials, submit payroll after settlement
- **base_manager** — maintain bases, publish jobs, review signups, generate salary drafts
- **field_manager** — on-site QR check-in, view signup/attendance sheets, handle on-site exceptions
- **super_admin** — audit registrations & changes, manage users, view logs, export salary & attendance reports

### Core Flow

1. Boss submits base registration → 2. Super admin audits base, assigns managers → 3. Base manager publishes jobs → 4. Worker browses & signs up in mini program → 5. Field manager scans worker QR for check-in → 6. System generates salary drafts from attendance → 7. Worker confirms or appeals → 8. Boss/admin completes payment, system archives & exports

## Architecture

### Monorepo Structure (npm workspaces at root)

```
apps/
├── backend/              # NestJS API server (MySQL, TypeORM, JWT, Swagger)
├── web-admin/            # React + Vite web management console
└── wechat-miniprogram/   # WeChat Mini Program (worker/boss/field-manager)
docs/                     # Design docs, test guides, operations, engineering standards
artifacts/                # Exported reports, screenshots, demo materials
```

### Backend (`apps/backend`)

NestJS modular monolith. All entities are registered globally in `AppModule` via `TypeOrmModule.forRootAsync` — individual modules do NOT use `TypeOrmModule.forFeature`.

**Modules** (`src/modules/`):
- `auth/` — JWT login, role guards (`RolesGuard`, `JwtAuthGuard`), `@Roles()` decorator, `jwt.strategy.ts`
- `user/` — user CRUD, real-name verification, proxy registration, audit
- `base/` — base management, jobs, applications, cooperation requests, supervisor assignment
- `attendance/` — signup, QR code generation, check-in, offline attendance
- `salary/` — salary calculation (`SalaryCalculatorStrategy`), auto-draft, payment, report submission, XLSX export
- `recommendation/` — base recommendation algorithm
- `dashboard/` — statistics dashboard
- `common/` — shared services: OperationLog, Security (encryption), SMS, Tencent COS/OCR, Backup

**Key infrastructure patterns:**
- `ConfigModule.forRoot({ isGlobal: true })` — env config available everywhere
- All entities listed explicitly in `TypeOrmModule.forRootAsync` entities array
- Global `ValidationPipe` with `whitelist`, `transform`, `forbidNonWhitelisted`
- Global API prefix: `/api`
- Swagger at `/docs`, Swagger JSON at `/docs-json`
- JWT auth via `@nestjs/jwt` + `@nestjs/passport`
- File uploads served via `app.useStaticAssets` under `/uploads/`

### Web Admin (`apps/web-admin`)

React 19 + Vite 6 + TypeScript + React Query + Tailwind CSS.

**Structure** (`src/`):
- `App.tsx` — routing & role-based access control via `ProtectedRoute` + `AuthContext`
- `views/` — page components (e.g., `BaseManagement.tsx`, `PayrollView.tsx`, `AuditCenter.tsx`)
- `layouts/` — `DashboardLayout`, `WarmDashboardLayout`
- `components/` — shared UI (`Header`, `Sidebar`, `AuthShowcase`)
- `api/` — auto-generated by Orval from Swagger (`src/api/generated/`, `src/api/model/`)
- `lib/http.ts` — custom Axios instance (Orval mutator)

**Key config:**
- Vite proxy: `/api` → `http://localhost:3001`
- Orval generates React Query hooks from `http://localhost:3001/docs-json`
- Path alias: `@/` → `src/`

### WeChat Mini Program (`apps/wechat-miniprogram`)

Vanilla WeChat mini program with custom tab bar and role-based navigation.

- `app.js` — request wrapper with cloud function proxy support, baseUrl resolution, image sanitization
- `pages/` organized by role: `index/` (worker square), `boss/`, `field/`, `admin/`, plus feature pages
- CloudBase integration for Phase 1 migration and API proxy via cloud functions
- Supports both direct HTTP and cloud-proxy modes

### Documentation (`docs/`)

- `docs/getting-started/` — setup guides, full-flow walkthrough
- `docs/design/` — system design, project plan, database schema
- `docs/testing/` — test guide, test accounts, integration checklist
- `docs/operations/` — pre-launch checklist, ops readiness
- `docs/engineering/` — Git conventions, commenting standards

## Key Patterns & Conventions

- **Role-based access** — Backend uses `@Roles()` decorator + `RolesGuard` (see `auth/guards/`); frontend uses `ProtectedRoute` with `UserRole` enum
- **Orval codegen** — API client and React Query hooks auto-generated from Swagger; run after backend changes
- **Comment style** — Files use a header comment block describing "Layer" and "Responsibility"; body comments explain "why", not "what"
- **DB schema** — Managed via TypeORM `synchronize` in dev (controlled by `DB_SYNCHRONIZE` env var); separate `migrations/` directory for production
- **Environment** — `.env` file required for backend (DB credentials, AES_KEY, JWT_SECRET, SMS/OCR secrets)
- **Cross-module services** — `OperationLogService` and `SecurityService` live in `common/` and are injected where needed
